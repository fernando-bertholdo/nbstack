### Added
- Eighth plugin: `decisoes` at `v0.1.0` (marketplace `0.8.17` → `0.9.0`; see [`plugins/decisoes/CHANGELOG.md`](./plugins/decisoes/CHANGELOG.md)). The first mod in the marketplace — a Claude Code plugin of function hooks (`hooks/hooks.json` with `modules`), not a skill. It collects, per session, the decisions only the session's owner can make — through a `registrar_decisao` tool the agent calls and through lines its answer flags with 🔴 — shows them in a band above the prompt, answers them one at a time in a `/decisoes` pane, sends the answers back as one turn, lists the other cmux sessions waiting on a decision and takes you to their tab, and asks a session to land before the machine closes. It was written for one person in a session on 04/10/2026 and lived only in a temporary folder; to publish it, the texts the agent reads name whoever a new `dono` option says (with the article, "o Fernando", "a Ana"; "o usuário" when empty) and "the machine" instead of a Mac, `plugin.json` gains author and license, and the test fixtures use neutral names. `claude plugin validate` passes with no warning and `claude plugin test` runs 9 of 9 (Claude Code 2.1.289); with `register` ignoring the option, its test fails. `CONTRIBUTING.md`'s structure tree now also lists `multica-ops` and `cmux-hibernate`, which it had missed since they were added.
- Sixth plugin: `multica-ops` at `v0.1.0` (see [`plugins/multica-ops/CHANGELOG.md`](./plugins/multica-ops/CHANGELOG.md)). Native, one skill (`board`): the operating manual for a Multica board from Claude Code, or from a Cowork/claude.ai session bridged to the machine running the desktop app. Discovery-first by design — the profile comes from `~/.multica/profiles`, workspaces from `workspace list`, every other id from the matching `list` command — so **no workspace id, project name or machine path ships in the public repo**; a private configuration repo can be pointed at via `MULTICA_PLAYBOOK` and the skill defers to its manifests and deploy tooling. Documents safe defaults (`--no-start` on every `issue status`, silence on unscoped issues, promotion and deploy reserved for a human, no casual `create`, a dated trace when a session acts under a human's profile), the CLI output shapes that are not arrays, the positional label argument, the 100-item page cap, the zsh word-splitting bugs behind the `mt()` wrapper, and the platform limits (per-workspace isolation, artifacts disabled inside agent tasks, no MCP surface). Measured against CLI v0.4.42. Marketplace version bumped `0.7.0` → `0.8.0`.

### Infrastructure
- Local `LOCAL-PATCH` blocks now survive the weekly upstream sync automatically. `_sync-skill-from-template.yml` runs the new [`scripts/reapply-local-patches.py`](./scripts/reapply-local-patches.py) right after `rsync --delete`, re-injecting each sentinel block from the committed (HEAD) file at its anchor. This prevents the spurious "patch removed" PR that would otherwise fire on the first sync of a patched plugin (e.g. `enhanced-planning`): a sync with no upstream change now produces no PR (the patch is restored byte-for-byte), and a real upstream change surfaces only that change plus the re-applied patch. The script only adds our own blocks, never edits upstream content, and is a no-op for patch-free plugins. Validated locally (no-change, real-change, and idempotency cases).

### Documentation
- Versioning table for vendored plugins ([`CLAUDE.md`](./CLAUDE.md), [`docs/promotion-runbook.md`](./docs/promotion-runbook.md) and the copy in [`plugins/prompt-master/README.md`](./plugins/prompt-master/README.md)): two rows for an upstream sync whose upstream version does not move, where the plain-sync row (only `+upstream-X.Y.Z`) would bump nothing. A sync that changes behavior — what the skill tells the agent to read, do or stop doing — bumps MINOR; one that changes only text bumps PATCH. `generate-session-prompt` `1.1.0+upstream-4.0.0` and `enhanced-planning` `1.1.0+upstream-2.0.0`, under *Changed*, are the first bumps under the MINOR row.
